# Приёмка пяти пользовательских сценариев

Дата проверки: 20 октября 2026. Проверка выполнена на локальном API `python -m app.server --data data/poi.astana.json`.

## Окружение и границы проверки

- `/api/health` вернул `status: ok`, `mode: extractive`, `places_count: 738`, `llm_configured: false`.
- Использован реальный набор OpenStreetMap из репозитория. В ответах указано, что сведения не проверены на месте; расстояния приблизительные.
- Запросы ниже отправлены напрямую на `POST /api/recommend` с теми же полями, что использует веб-интерфейс.
- Браузерная проверка интерфейса не выполнена: инструмент управления текущим Windows-браузером остановился из-за неподдерживаемой проверки URL. Поэтому здесь зафиксированы результаты API, а не E2E-прохождение UI.
- LLM не была настроена; результаты получены в `extractive`-режиме и не подтверждают работу генератора.
- В проекте указано требование Python 3.11+. Доступен Python 3.10.11; команда `python -m unittest discover -s tests -v` завершилась с 2 failures и 1 error. Ошибки: `test_network_pagination_is_bounded_and_stops_on_short_page` и `test_replay_is_loadable_and_marked_source_data_not_demo` получили код возврата 1; `test_collection_astana.RealAstanaDataTests.setUpClass` завершился `UnicodeDecodeError` при чтении JSON через системную кодировку `cp1252`. Полный прогон на поддерживаемом Python не выполнен.

### Повторный запуск на поддерживаемом Python

20 октября тесты повторно запущены на доступном Python 3.12.14 из bundled workspace runtime; временные файлы направлены в доступный для записи каталог workspace. Из 33 тестовых случаев два завершились ошибкой, остальные прошли:

- `test_network_pagination_is_bounded_and_stops_on_short_page`: тест читает созданный JSON без указания UTF-8 и завершился `UnicodeDecodeError` (`cp1252`, байт `0x9d`).
- `test_collection_astana.RealAstanaDataTests.setUpClass`: `tests/test_collection_astana.py` читает JSON без указания UTF-8 и завершился `UnicodeDecodeError` (`cp1252`, байт `0x9d`).

Таким образом, прежние сбои двух тестов 2ГИС из-за недоступного системного временного каталога при первом запуске в sandbox не воспроизвелись после перенаправления временных файлов в workspace. Оставшиеся две ошибки — проблемы декодирования UTF-8 JSON при системной кодировке Windows; код тестов не менялся в рамках этой QA-задачи.

## Найденные проблемы

### QA-01 — семейный сценарий возвращает кафе вместо запрошенной категории

- **Шаги:** запустить сервер с `data/poi.astana.json`; отправить `POST /api/recommend` с `query="С ребёнком, площадка или парк"`, `minutes=60`, `origin={"lat":51.1546,"lon":71.4252}`, `time_of_day="day"`.
- **Ожидалось:** рекомендации ограничены парками/площадками или другим явно подтверждённым семейным местом.
- **Фактически:** кроме парка Астана API вернул Bon coffee (`osm:node/12973350281`, категория `cafe`).
- **Подтверждение:** JSON ответа API в этом прогоне; у Bon coffee категория `cafe`, а запрос содержит только ребёнка, площадку или парк.

### QA-02 — туристический запрос об архитектуре возвращает места без очевидной связи с архитектурой

- **Шаги:** запустить сервер с `data/poi.astana.json`; отправить `POST /api/recommend` с `query="Турист, хочу архитектуру"`, `minutes=120`, `origin={"lat":51.1283,"lon":71.4305}`, `time_of_day="day"`.
- **Ожидалось:** архитектурные достопримечательности или явное уточнение при отсутствии подходящих POI.
- **Фактически:** API вернул НЛО (`osm:way/1449322337`) и Динопарк (`osm:way/1449322339`), оба с категорией `attraction`.
- **Подтверждение:** JSON ответа API в этом прогоне; выданные названия и категории не указывают на архитектуру. Причина не предполагается.

## Воспроизведение

