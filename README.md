# Astana Walks

ИИ-помощник по прогулкам в Астане для задачи №1 НИЦ Smart City, Build with AI / GDG Astana.

Выберите старт, интересы и запас времени. Приложение подбирает до трёх реальных мест, объясняет выбор, предлагает занятие и оценивает прогулку с возвращением к старту. Каждая рекомендация содержит источник и предупреждения о неизвестных свойствах.

**Состояние на 20 октября 2026:** рабочая версия находится в [`codex/completion-local`](https://github.com/ltybcs/astana-walks-ai/tree/codex/completion-local), итоговая интеграция идёт в [draft PR #5](https://github.com/ltybcs/astana-walks-ai/pull/5). PR #6 с QA, #7 с PWA, #9 с инструкциями установки и #10 с двумя видеофрагментами объединены. Возможности ниже относятся к этой рабочей версии; перед запуском переключитесь на указанную ветку.

| Часть | Проверенное состояние |
| --- | --- |
| Данные | 738 POI из OpenStreetMap; исходный ответ, запрос, дата и лицензия сохранены |
| Backend и PWA | 87/87 автоматических тестов; пять сценариев проверяют ограничения и источники |
| Настоящий телефон | Пользователь подтвердил установку и запуск по иконке в Android Chrome |

[Временное HTTPS-демо](https://entire-burn-cricket-ashley.trycloudflare.com/) доступно при включённых ПК, приложении и туннеле. Сервис подключён к проверенной на сценариях локальной 4B-модели. Фактический режим каждого ответа показан в интерфейсе; при ошибке или отклонении генерации используется обозначенный extractive fallback.

## Быстрый старт

Нужен Python 3.11 или новее. Для самого приложения сторонние Python- и JavaScript-пакеты не требуются.

```sh
git clone https://github.com/ltybcs/astana-walks-ai.git
cd astana-walks-ai
git switch codex/completion-local
python -m app.server --data data/poi.astana.json
```

Репозиторий закрытый: для клонирования нужен предоставленный доступ GitHub. Если исходники уже получены архивом указанной рабочей ветки, выполните только последнюю команду из папки проекта. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Сервер по умолчанию доступен только на этом компьютере.

Без модели работает extractive fallback. Режим `llm-grounded` означает, что приняты свободные объяснения LLM по найденным POI. При ошибке, таймауте или отклонённом ответе приложение возвращается к extractive и показывает предупреждение. Режим виден в интерфейсе и JSON API.

## Локальная LLM без облачного ключа

Для Windows x64 подготовлен CPU-запуск **Qwen3-4B-Instruct-2507 Q4_K_M** через **llama.cpp b11739**. GGUF опубликован Unsloth на основе Qwen, лицензия Apache-2.0. Runtime и веса закреплены по версии и SHA-256. Веса занимают около 2,5 ГБ, загружаются отдельно и не попадают в Git.

Если сервер из быстрого старта ещё работает на порту 8000, остановите его через Ctrl+C в его терминале перед запуском `run_demo.py`.

```sh
python scripts/setup_local_llm.py --download
python scripts/run_demo.py --data data/poi.astana.json --local-llm
```

Веса 4B загружены, их SHA-256 проверен, сервер запущен. В живом прогоне пройдены 5 основных сценариев и дополнительный семейный запрос: 5 обращений к модели без повторной генерации. Все 7 пар объяснений и действий прочитаны двумя агентами; в отчётах стоит `manual_review.quality_pass=true`. Это оценка конкретных ответов, а не гарантия будущего текста или условий на месте. Предыдущая 1.7B не прошла чтение по смыслу; её отчёты с `quality_pass=false` сохранены в `output/history/qwen3-1.7b/`. Итоговая live-сборка требует явного положительного review в отчёте и файле объяснений.

`run_demo.py` запускает приложение на `127.0.0.1:8000`, модель на `127.0.0.1:8081` и завершает оба процесса по Ctrl+C. Он сам задаёт окружение дочернему приложению. На Linux/macOS либо с другой моделью запустите совместимый Chat Completions API самостоятельно и задайте переменные окружения перед `python -m app.server`. Для loopback ключ не требуется; для внешнего HTTPS endpoint нужен `LLM_API_KEY`. Файлы `.env` автоматически не читаются.

Для локального сервера параметры такие. В отдельном терминале PowerShell этот блок также нужен перед **живой оценкой**: окружение дочернего сервера не переходит в другой терминал.

```powershell
$env:LLM_BASE_URL = 'http://127.0.0.1:8081/v1'
$env:LLM_MODEL = 'astana-local'
$env:LLM_JSON_MODE = 'schema'
$env:LLM_TOKEN_PARAMETER = 'max_tokens'
$env:LLM_TIMEOUT_SECONDS = '120'
```

Поддерживаются `LLM_JSON_MODE=schema/json/none` и `LLM_TOKEN_PARAMETER=max_tokens/max_completion_tokens` в зависимости от провайдера. Ключи не записываются в код и документы.

## Установка на телефон

Откройте HTTPS-демо во внешнем браузере телефона и нажмите **«Установить»**. Если системное окно недоступно, откроется ручная инструкция:

- **Chrome на Android:** установка через предложение или меню браузера.
- **Firefox на Android:** меню ⋮ → «Установить» → добавление на домашний экран; названия зависят от версии. [Инструкция Mozilla](https://support.mozilla.org/ru/kb/ispolzovanie-veb-prilozhenij-s-firefox-dlya-androi).
- **Safari на iPhone:** «Поделиться» → «На экран “Домой”».

Установка и запуск по иконке в Android Chrome подтверждены пользователем (`output/phone-check.json`). Для Firefox на Android добавлена ручная инструкция; успешная установка на другом устройстве ещё не подтверждена. iPhone, модель телефона и работа без сети на физическом устройстве не проверялись.

PWA сохраняет оболочку и иконки. Новый подбор требует соединения с backend. API, запросы, координаты и ответы service worker не кэширует; старые рекомендации не выдаются за новый результат. Для телефона `localhost` компьютера не подходит: нужен HTTPS-адрес сервиса. Схема временного доступа описана в `docs/HTTPS_DEMO.md`; модель на порту 8081 отдельно не публикуется.

## Данные и подбор

Рабочий набор `data/poi.astana.json` содержит **738 POI**, автоматически собранных из OpenStreetMap. Исходный ответ и Overpass-запрос находятся в `data/snapshots/`, происхождение и ограничения — в `data/SOURCES.md`. Это snapshot, а не гарантированно актуальное расписание города: для 492 мест часы неизвестны. Отсутствие часов не означает, что место открыто. Полевой проверки нет.

```sh
python scripts/collect_osm.py --output data/poi.osm.json
python -m app.server --data data/poi.osm.json
```

Сбор требует сети; параметры доступны через `--help`. При сетевой ошибке существующий набор сохраняется. Новые выгрузки игнорируются Git по умолчанию. `data/poi.sample.json` — отдельный учебный набор для тестов, не городской каталог.

Подбор использует BM25, расстояние, доступное время, категории и ограничения запроса. Повторные записи одного физического места убираются. Розетка, доступность для коляски и ночное открытие требуют подтверждения в данных; без него возможен объяснённый пустой ответ. Время включает возврат и оценивается по прямой дистанции с коэффициентом, а не по дорожному графу. Схема в интерфейсе не заменяет навигатор.

Модель получает структурированные интересы и публичные факты о найденных POI, без полного запроса и точных координат пользователя. Backend проверяет идентификаторы, ссылки на источники, поля фактов и защищённые утверждения. Эти проверки снижают риск выдумок, но не доказывают смысловую корректность каждой свободной фразы.

Данные требуют атрибуции [© OpenStreetMap contributors, ODbL](https://www.openstreetmap.org/copyright). Лицензия данных и лицензии моделей не являются лицензией кода проекта.

### Необязательный сборщик 2ГИС

Есть сборщик официального Places API, но реальный набор 2ГИС пока не получен. Тесты сборщика используют синтетические ответы. Для своего запуска получите [ключ 2ГИС](https://docs.2gis.com/platform-manager/subscription/keys), задайте `DGIS_API_KEY` в окружении и выполните:

```sh
python scripts/collect_2gis.py --output data/poi.2gis.json
python -m app.server --data data/poi.2gis.json
```

Сохранённый ответ можно нормализовать без сети через `--input`; остальные параметры доступны через `--help`. Ключи и выгрузки не коммитятся.

## Проверка и контейнер

```sh
python -m unittest discover -s tests -v
python -m app.evaluate --data data/poi.astana.json --output output/evaluation.json --run-tests
```

Последний локальный suite: **87/87**, без пропусков. Для исполнения проверок service worker и установки нужен доступный Node.js; приложение от Node.js не зависит. Сценарии: короткая прогулка у MEGA, кофе с розеткой, ребёнок, туристическая архитектура, ночная активность. Проверяются бюджет с возвратом, источники, ограничения, дубли и объяснение отказа. Пять успешных сценарных проверок не равны ручной оценке текста LLM.

Переносимый запуск из чистого Git ZIP на Python 3.12.14 без сторонних пакетов и LLM прошёл 16/16 отдельных проверок (`output/portable-check.json`). Это проверка запуска и HTTP, а не дополнительная сертификация текста модели или физического телефона.

Живая оценка вызывает настроенного провайдера. Сначала запустите модель и задайте окружение в терминале оценки, как показано выше, затем:

```sh
python -m app.evaluate --data data/poi.astana.json --output output/evaluation-live.json --run-tests --llm
```

Отчёт фиксирует режим каждого ответа, обращения к LLM, число POI и SHA-256 набора. Текущий `output/evaluation-live.json` относится к 4B и содержит 87/87 тестов, 5/5 основных сценариев и отдельную семейную проверку. LLM принята во всех 4 непустых основных случаях; кофе с неподтверждённой розеткой даёт объяснённый отказ без вызова модели. С учётом дополнительного семейного запроса записано 5 LLM-вызовов. Публичные request/response и закреплённый manifest модели сохранены в `output/llm-evidence/` без ключей и личной локации. Исторический неудачный прогон 1.7B сохранён отдельно с SHA-256 исходных файлов.

```sh
docker build -t astana-walks .
docker run --rm -p 127.0.0.1:8000:8000 astana-walks
```

Контейнер запускает приложение без весов модели. CI проверяет тесты, сборку контейнера, health и статические ресурсы. Для полного локального RAG используется отдельный запуск модели.
