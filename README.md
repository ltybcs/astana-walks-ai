# Astana Walks

ИИ-помощник, который помогает выбрать, чем заняться в Астане, и составить пеший маршрут под свободное время.

Проект разработан для **Build with AI / GDG Astana**, задача №1 НИЦ Smart City.

**[Открыть демо](https://ltybcs.com/demo)** · **[Видео на YouTube](https://youtu.be/QJCgEYHDqBU)**

## О проекте

В незнакомом районе сложно быстро выбрать подходящее место: нужно сравнить расстояния, учесть время и понять, соответствует ли заведение пожеланиям. Astana Walks объединяет эти шаги в одном запросе:

> «У меня 45 минут возле Mega, хочу короткую прогулку».

Сервис рассчитан на жителей, туристов и семьи с детьми. Вместо самостоятельного просмотра нескольких каталогов он предлагает места, объясняет выбор и показывает один маршрут с остановками и возвращением к старту.

## Возможности

- **Запрос обычным текстом.** Место, длительность и пожелания извлекаются из сообщения.
- **Три источника в одном поиске.** Локальный каталог OpenStreetMap, Google и 2ГИС проверяются параллельно.
- **Учёт контекста.** Подбор учитывает время, расстояние, тип занятия и явно указанные условия — например, ребёнка, тишину или розетку.
- **Мини-маршруты.** До трёх остановок, пешие переходы, предложенное время посещений и запас; для отдельного занятия может выбираться одно заведение.
- **Объяснения и источники.** У каждого места есть описание, пояснение выбора и ссылка на исходные данные.
- **Одна карта маршрута.** Она появляется после построения плана. Готовые варианты времени переключаются без повторного поиска.
- **Мобильный интерфейс и PWA.** Сайт можно добавить на главный экран; поиск и карта требуют подключения к сети.

## Как пользоваться

1. Откройте [демо](https://ltybcs.com/demo).
2. Напишите, где вы, сколько у вас времени и чем хотите заняться.
3. Нажмите «Найти прогулку». Если старт не указан, разрешите геолокацию.
4. Выберите вариант, посмотрите остановки и откройте маршрут на карте.

Без указанной длительности предлагаются варианты на **1, 2 и 4 часа**. Для свободного дня — на **4, 6 и 8 часов**. Время суток определяется автоматически, если оно не задано в сообщении.

## Сценарии использования

| Пример запроса | Ожидаемое поведение |
| --- | --- |
| «Я возле Mega Silk Way, хочу прогуляться 30–60 минут». | Короткий маршрут с вариантами длительности и возвращением к старту. |
| «Хочу тихое место с кофе и розеткой недалеко от Байтерека». | Поиск кафе с учётом условий; неизвестная розетка или тишина не выдаётся за подтверждённый факт. |
| «Еду с ребёнком в центральный парк — где рядом есть детские площадки или музей с интерактивами?» | Семейный сценарий; тип музея сам по себе не считается доказательством интерактивной программы. |
| «У меня 1,5 часа, я около EXPO, хочу увидеть природу Астаны». | Поиск парков и зелёных пространств с бюджетом 90 минут. |
| «Хочу поиграть в компьютерном клубе, есть пять часов около Абу Даби». | Подбор компьютерного клуба с учётом пути и времени посещения. |
| «Дай парки, в которые можно сходить ближайшие два часа рядом со мной». | Определение старта через GPS и поиск парков на 120 минут. |

Подробные проверки и ожидаемые результаты — в [тестовых сценариях](docs/CURRENT_SCENARIOS.md).

## Как работает ИИ и RAG

**RAG** связывает генерацию ответа с найденными данными о местах — POI (points of interest).

1. **Понимание запроса.** Локальная модель выделяет цель, старт и условия. Названное место проверяется по справочнику или через Google Places; при отсутствии старта используется разрешённая геолокация.
2. **Поиск и отбор.** Система получает кандидатов из трёх источников, проверяет соответствие цели и доступные сведения. Google рассчитывает пешие участки, включая возвращение; приложение проверяет общий бюджет времени.
3. **Объяснение результата.** Модель получает отобранные факты и формирует описания. Упомянутые места сверяются с найденными, а утверждения о свойствах проходят отдельные проверки. Если итоговый текст не проходит проверку, карточка сохраняет описание по данным источника с пометкой «Идея приложения».

Часы работы, оборудование и доступность берутся из данных места. Предложенное занятие и длительность посещения отделяются от этих фактов. Полный ответ Google и ссылки на его источники доступны в раскрываемом пояснении.

## Установка и запуск

Нужны Python 3.11+, Git, современный браузер и интернет. Для полного подбора нужны запущенная локальная модель и настроенные API Google и 2ГИС. Ключи и веса модели в репозиторий не входят.

```sh
git clone https://github.com/ltybcs/astana-walks-ai.git
cd astana-walks-ai
```

Подготовьте модель, переменные окружения и приватные конфигурации по [инструкции запуска](docs/DEPLOYMENT.md). После подготовки в PowerShell:

```powershell
python -m app.google_lab --host 127.0.0.1 --port 8000 --llm --google --google-config $taskGoogleConfig --dgis-root $taskPrimary --map-config $taskEmbedConfig
```

Здесь `$taskGoogleConfig`, `$taskPrimary` и `$taskEmbedConfig` — пути, заданные на шаге настройки из инструкции. Откройте **http://127.0.0.1:8000/**. Остановка приложения — `Ctrl+C`.

## Как проверить решение

Для знакомства используйте запросы из таблицы сценариев. Проверьте соответствие места пожеланию, время переходов и посещений, описание остановок и ссылки на источники.

Автоматические проверки из корня проекта:

```sh
python -m unittest discover -s tests -v
```

Node.js нужен для проверок интерфейса и PWA. Тесты подменяют ответы внешних API, модели и геолокации, поэтому не расходуют запросы провайдеров и не заменяют живую проверку конкретного места.

## Данные и конфиденциальность

OpenStreetMap используется как локальный каталог, Google и 2ГИС — как внешние источники поиска. В условиях использования указано, какие сведения о старте и поисковых пожеланиях передаются внешним источникам. Подготовленный запрос и координаты обрабатываются в памяти; PWA сохраняет только оболочку приложения.

Секретные ключи остаются на сервере. Для карты используется отдельный браузерный ключ с ограничениями API и адресов сайта. Неизвестные часы, розетки и другие свойства не считаются подтверждёнными, а при отсутствии подходящих данных система сообщает об этом.
