# Источники городских данных

## 2ГИС

Пользователь предложил 2ГИС для проверки мест Астаны. Публичные карточки можно
открыть из рекомендаций; воспроизводимый сбор выполняет отдельный
`scripts/collect_2gis.py` через официальный Places API.

Документация: [обзор](https://docs.2gis.com/api/search/places/overview),
[параметры поиска](https://docs.2gis.com/api/search/places/reference/3.0/items),
[получение ключа](https://docs.2gis.com/platform-manager/subscription/keys).

Ключ берётся только из `DGIS_API_KEY`. Он не передаётся через аргументы командной
строки и не попадает в набор данных или сообщения об ошибках. Сборщик не использует
куки и ключ публичного сайта. Перенаправления API-запросов отключены, чтобы ключ
не оказался на другом сервере.

Команда по умолчанию делает до шести запросов: по одной странице из 50 результатов
для кофеен, музеев, парков, достопримечательностей, детских площадок и торговых
центров. `--pages` задаёт верхнюю границу страниц на запрос. Результат — ограниченная
выборка, а не полный городской каталог. Географические границы проверяются и в
запросе, и после получения координат. Дубликаты удаляются по ID источника.

Каждый POI содержит ссылку на карточку, время получения, категорию источника и
статус `source_reported_not_field_verified`. Получение карточки не подтверждает
доступность места сейчас. Отсутствующие характеристики остаются неизвестными:
Wi-Fi и возможность работать с ноутбуком не подтверждают наличие розеток или тишину.
24/7 выставляется только при полном явном недельном расписании 00:00–24:00 без
особого расписания. Неполные часы не превращаются в доступность ночью.

Рейтинг и отзывы не импортируются. Проверки в браузере хранят только несколько
коротких фактических заметок в `2gis_reference_checks.json`; это указатель на
источники, он не загружается приложением и не заменяет автоматизированный сбор.

Выгрузка `poi.2gis.json` локальная и игнорируется Git. Данные 2ГИС имеют собственные
условия использования; право хранения, срок обновления и распространение нужно
сверять с условиями аккаунта API. Они не получают лицензию ODbL от соседнего набора
OSM. Не объединяйте их с OSM без сохранения происхождения и условий источников.

## OpenStreetMap

`scripts/collect_osm.py` остаётся независимым источником. Он сохраняет дату,
OSM-ссылки и атрибуцию © OpenStreetMap contributors / ODbL. Подробности — в README
и [условиях OSM](https://www.openstreetmap.org/copyright).

20 октября 2026 получен реальный снимок официального Overpass: 738 именованных
POI в границах 51.02, 71.30, 51.22, 71.55. Время базы OSM:
`2026-10-19T19:15:01Z`. Нормализованный набор — `poi.astana.osm.json`, исходный
ответ и точный запрос — `snapshots/astana-2026-10-20.overpass.json` и `.overpassql`.
Даты отдельных объектов сохраняются как `source_updated_at`; свежий снимок
базы не означает, что каждое место недавно проверялось.

Повторная автоматическая загрузка с теми же параметрами:

```sh
python scripts/collect_osm.py --output data/poi.astana.osm.json
```

Воспроизведение нормализации сохранённого снимка без сети:

```sh
python scripts/collect_osm.py --input data/snapshots/astana-2026-10-20.overpass.json --output tmp/replayed-astana.json
```

Сравнивать нужно `places`: время нормализации при повторном запуске меняется.
Часть метаданных о сохранённых файлах добавлена при комплектации снимка и не
изменяет факты POI. В наборе 492 точки без часов работы. Несколько OSM-объектов
могут описывать одно физическое место; известный пример — node и way MEGA Silk Way.
Планировщику нужно исключать повторные остановки на одном месте. Проверка пяти
синтетических запросов выявила также необходимость улучшить ранжирование
туристических запросов; эти замечания переданы владельцу backend.

## Статус проверки

20 октября 2026: в Chrome открыты карточки MEGA Silk Way, Национального музея РК
и Coffee BOOM в MEGA. Их сведения не проверялись на месте. API-сборщик проверен
на синтетических ответах и офлайн-воспроизведении; реальный запрос с собственным
ключом пока не выполнен. Учебный набор приложения остаётся исходным.
