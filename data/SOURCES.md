# Источники городских данных

## 2ГИС

2ГИС подключён как отдельный поиск по категории в интерфейсе через официальный
Places API `catalog.api.2gis.com`. Он не является постоянным каталогом RAG:
карточки не добавляются в OSM, индекс, контекст модели или маркеры карты.

Документация: [обзор](https://docs.2gis.com/api/search/places/overview),
[параметры поиска](https://docs.2gis.com/api/search/places/reference/3.0/items),
[получение ключа](https://docs.2gis.com/platform-manager/subscription/keys).

Сервер берёт ключ из `DGIS_API_KEY` либо локального игнорируемого файла
`.local/2gis/api-key`. Ключ не передаётся браузеру, в аргументах командной строки,
Git, health или сообщениях об ошибках. Нет использования cookie/ключа публичного
сайта; перенаправления запросов отключены.

Один явный поиск делает одну попытку и возвращает первую страницу до 10 карточек.
Это [максимальный размер страницы для демо-ключа](https://docs.2gis.com/en/api/search/places/examples/results),
а не полный каталог. Категория выбирается из фиксированного списка, bbox Астаны
постоянный: пользовательский текст и координаты не отправляются провайдеру.
У ответа есть атрибуция и ссылки на карточки источника; часы и неизвестные
характеристики не превращаются в подтверждённое открытие или пригодность места.

Лимит приложения — 20 попыток за скользящие 24 часа на весь экземпляр сервера,
включая ошибки и диагностику. Попытка резервируется до сети; атомарный счётчик и
межпроцессный lock хранятся в `.local/2gis/`. Повреждение счётчика запрещает новые
обращения, а не обнуляет расход. Нет повторов, фонового опроса или публичного
endpoint обхода лимита. Лимиты аккаунта провайдера действуют дополнительно.

По [пункту 3.1 опубликованной оферты](https://law.2gis.ru/webapi-offer) кеширование
полученных продуктов не предусмотрено; извлечение и сохранение ограничены
договором. Поэтому ответы живого поиска остаются только в текущем ответе/DOM,
HTTP имеет `no-store`, service worker API не сохраняет. На диске есть только
время попыток, без карточек, названий, адресов или raw-ответов. Для постоянного
снимка и суточного обновления используется отдельно лицензированный OSM.

`scripts/collect_2gis.py` сохранён как отдельный инструмент нормализации/экспорта
для договоров с явно разрешённым хранением. В этом демо экспорт реальных данных
2ГИС не используется. Его default page size также 10; увеличение до 50 относится
к подходящей подписке. Синтетические тесты сборщика не доказывают право хранения.
Лицензия ODbL соседнего набора OSM на 2ГИС не распространяется.

## OpenStreetMap

`scripts/collect_osm.py` остаётся независимым источником. Он сохраняет дату,
OSM-ссылки и атрибуцию © OpenStreetMap contributors / ODbL. Подробности — в README
и [условиях OSM](https://www.openstreetmap.org/copyright).

Текущий `poi.astana.json` содержит **1267 OSM-объектов** в прямоугольнике
`51.00, 71.20, 51.32, 71.70` (south, west, north, east). Это ограниченный срез
городской территории Астаны, а не административная граница и не полный каталог.
Дата базы OSM: `2026-10-19T21:29:20Z`; получение: `2026-10-19T21:30:22+00:00`.
Сохранены исходные байты ответа и точный запрос:
`snapshots/astana-2026-10-19T213022966728Z.overpass.json` и `.overpassql`.

SHA-256 нормализованного файла:
`07dc0a3eb3a9b76b1c8121253cf5c5f1f46d67d991c5eb6b7823d45fccc0aa1e`.
SHA-256 raw:
`fec3f809a9f46f72e047cf534083e5d6735812f0f88246bae402f01e463e3239`.
SHA-256 query:
`3c346b4a1a3a1d8873f79f563b1d4057c3699adc75fbf85873823644dc26b78a`.

Категории: кафе 341, рестораны 176, бары 106, парки/сады 177, детские площадки
342, торговые центры 53, памятники 39, достопримечательности 16, музеи 8, театры 9.
Все 738 ID предыдущего снимка сохранены; добавлено 529 ID. Это число объектов
источника: node/way могут описывать одно физическое место, поэтому планировщик
дополнительно выполняет дедупликацию. Даты объектов сохраняются как
`source_updated_at`; дата базы не означает полевой проверки каждого места.

Профиль `astana_walk_v2` включает названия `name`, `name:ru`, `name:kk`, `name:en`.
У парков/садов и детских площадок название необязательно: 478 объектов без имени
получили явную подпись «Без названия: категория (OSM тип/ID)», а не выдуманное
собственное имя. У таких POI `name_generated=true`, `source_name=null`;
`source_name_field` указывает фактический выбранный тег у именованных мест.
`source_tags` содержит только фактические теги OSM, синтетический `name` туда не
добавляется. В метаданных набора сохранены `unnamed_count` и `label_policy`.
Кафе, музеи и остальные категории без названия не включаются. 789 объектов имеют
имя в источнике. Неизвестные розетки, тишина, доступность и часы остаются неизвестными.

Исторический снимок из 738 именованных POI в границах
`51.02, 71.30, 51.22, 71.55`, OSM `2026-10-19T19:15:01Z`, по-прежнему сохранён
в `snapshots/astana-2026-10-20.overpass.json` и `.overpassql`.
Его прежние evaluation/LLM-доказательства архивированы отдельно; они не описывают
новое покрытие. Увеличение количества POI может менять рекомендации и длительность
маршрута без изменения запроса. Например, семейный пресет теперь включает
реальную площадку и парк; прежние 34 минуты не фиксируются искусственно.

Повторная автоматическая загрузка с теми же параметрами:

```sh
python scripts/collect_osm.py --output tmp/poi.candidate.json
```

Воспроизведение нормализации сохранённого снимка без сети:

```sh
python scripts/collect_osm.py --input data/snapshots/astana-2026-10-19T213022966728Z.overpass.json --output tmp/replayed-astana.json
```

Сравнивать нужно нормализованные факты, исключая новую дату получения. Для точного
replay исторического профиля укажите `--profile legacy_named --bbox 51.02 71.30
51.22 71.55`. Проверки snapshot используют профиль и bbox из метаданных.
Новые JSON/query записываются байтами UTF-8 с LF; переносы строк после оценки
не преобразуются, поэтому SHA относится к тем же байтам, что идут в поставку.

### Обновление из интернета

```sh
python scripts/run_demo.py --local-llm --refresh-poi
python scripts/refresh_poi.py
python scripts/refresh_poi.py --force
```

`--refresh-poi` (либо локальная переменная `POI_REFRESH_ENABLED=1`) включает
фоновый worker с TTL 24 часа. Сначала сразу используется валидный shipped snapshot
или более новый валидный локальный cache. Свежесть считается от `collected_at`:
новый shipped snapshot не скачивается повторно из-за отсутствия файла state.
Без флага сервер не обновляет данные по сети. Отдельный CLI проверяет TTL один
раз; `--force` обходит только суточный TTL, но не часовой cooldown; `--watch`
поддерживает тот же фоновый режим. Персональные координаты и пользовательские
запросы не участвуют в сборе — запрос всегда содержит фиксированный городской bbox.

Cache, raw/query и состояние хранятся в игнорируемой `.local/poi/`. Есть
межпроцессный lock, не более одного запроса одновременно, не более двух попыток
на обновление, timeout и ограничение ответа 25 MB. Между повторными попытками
выдерживается 30 секунд; после ошибки — часовой cooldown, сохраняемый между
перезапусками. Некорректный state однократно исправляется с сохранением cooldown.
Публичного force-refresh API нет, HTTP-запросы пользователей сеть не запускают.

Новый raw/query сохраняется вместе с датой/ODbL; JSON, координаты, границы,
источники и индекс проверяются до атомарной публикации нормализованного файла.
NaN/Infinity, повторные JSON-ключи и частичные ответы Overpass отвергаются.
Ошибка оставляет прежние файл и индекс пригодными к работе без интернета.
HTTP-обработчик удерживает один snapshot индекса на запрос, поэтому параллельное
обновление не смешивает две версии POI в одном ответе. Обычный `data/poi.astana.json`
фоновый процесс не перезаписывает; для новой поставки кандидат проверяется отдельно.

`/api/health.refresh` показывает включение, состояние, TTL, источник shipped/cache,
`last_good_at`, `last_attempt_at`, `next_check_at`, `stale` и безопасный код ошибки.
В нём нет raw URL, ключей и запросов. Это статус локального cache, а не гарантия
актуального открытия заведений. Непрерывный refresh при запуске без сети нельзя
обещать: используется последний пригодный снимок.

Схема cache/редких обновлений следует
[рекомендациям публичного Overpass](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html).
Для большой публичной нагрузки нужен собственный/выделенный источник данных;
публичный Overpass не используется как backend каждого пользовательского поиска.

## Статус проверки

20 октября 2026: фактический поиск кафе в публичном HTTPS-интерфейсе вернул
10 карточек и 10 ссылок источника. С учётом начальной диагностики потрачено
5 попыток, наблюдаемый остаток — 15/20; это историческое наблюдение, текущий
остаток показывает интерфейс. `output/2gis-check.json` содержит только метаданные
этой проверки, без ответов провайдера и ключа. Другие категории и полная база
этим не сертифицированы; полевой проверки нет. Основной OSM-набор — реальный
снимок выше; `poi.sample.json` остаётся явно учебным примером.
