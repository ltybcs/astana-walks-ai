# Временное HTTPS-демо на телефоне

Подготовлен вариант Cloudflare Quick Tunnel. Туннель ещё не запускался; провайдер и режим доступа требуют решения пользователя перед `--serve`.

Quick Tunnel выдаёт временный HTTPS-адрес `*.trycloudflare.com` без аккаунта и домена. Адрес меняется при новом запуске и прекращает работать после остановки процесса. Это вариант для короткого демо с включённым Windows-компьютером, а не постоянный адрес установленного приложения. [Официальная документация](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/). Cloudflare описывает Quick Tunnels как бесплатные временные туннели в [анонсе CLI-команд](https://developers.cloudflare.com/changelog/post/2026-03-19-wrangler-tunnel-commands/).

Трафик телефона проходит через Cloudflare к приложению `127.0.0.1:8000`. Qwen остаётся на ПК, её порт `8081` туннель не публикует. HTTPS необходим для обычной установки PWA на телефоне, но сам туннель не добавляет manifest или поддержку установки: их и повторный запуск с домашнего экрана нужно проверить отдельно. Service worker может дать автономную оболочку, однако не обязателен для установки. Без работающего ПК и сети модель на телефоне не отвечает. [Требования к установке PWA](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Подготовка без публикации

Нужны Windows x64 и Python 3.11+. В одном терминале приложение и локальная модель запускаются обычным способом:

```powershell
python scripts/run_demo.py --data data/poi.astana.json --local-llm
```

В другом терминале можно подготовить runtime и проверить приложение. Эти команды не создают туннель:

```powershell
python scripts/run_https_demo.py --download
python scripts/run_https_demo.py --check
```

`--download` получает только официальный `cloudflared-windows-amd64.exe` версии `2026.10.0`; скрипт сверяет SHA-256 `86aee4017b26625cee8484c113558f48effa4cd47f7aa05fcf425604e5d2b23c`. Версия и checksum опубликованы в [релизе Cloudflare](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.0). Файл хранится в игнорируемой `.local/cloudflared/`. `--check` сверяет этот файл и выполняет только GET локального `/api/health`, без запроса к LLM. Отсутствующий runtime означает код завершения 1.

## Запуск после решения пользователя

Предпочтителен доступ по конкретному email. Посетитель получает одноразовый PIN, аккаунт Cloudflare ему не нужен. Этот режим появился 2 октября 2026 и присутствует в закреплённом runtime. Указать следует реальный адрес допущенного пользователя; пример ниже сам по себе ничего не публикует. [Анонс Cloudflare](https://developers.cloudflare.com/changelog/post/2026-10-02-protected-quick-tunnels/), [исходный код закреплённой версии](https://github.com/cloudflare/cloudflared/blob/2026.10.0/cmd/cloudflared/tunnel/quick_tunnel.go).

```powershell
python scripts/run_https_demo.py --serve --allowed-mail YOU@example.com
```

Для нескольких разрешённых адресов повторить `--allowed-mail`. Только если пользователь выбрал доступ для любого обладателя ссылки:

```powershell
python scripts/run_https_demo.py --serve --public
```

Открыть напечатанный HTTPS-адрес в браузере телефона. Проверить подбор, источник и фактический режим ответа; затем установку и повторный запуск PWA. Для email-защиты отдельно проверить вход из установленного приложения. Остановить туннель через Ctrl+C и убедиться, что адрес больше недоступен. Скрипт завершает только созданный им процесс; приложение и модель продолжают работать. Он не устанавливает системную службу, не меняет firewall и не создаёт аккаунт.

## Условия и границы

Публичный режим даёт любому обладателю ссылки доступ к UI и API подбора; ссылки недостаточно для ограничения пользователей. При email-защите Cloudflare обрабатывает также адрес и PIN. В обоих случаях через провайдера проходят HTTP-запросы, включая введённый текст и отправленные координаты. Заявление о полностью локальной обработке для этого режима неприменимо; для демонстрации следует выбрать смоделированный старт. Приложение не сохраняет историю, но это не обещание об обработке данных внешним провайдером. Действуют [условия Cloudflare](https://www.cloudflare.com/website-terms/) и [политика приватности](https://www.cloudflare.com/privacypolicy/).

Quick Tunnel не гарантирует доступность, допускает до 200 одновременных запросов и не поддерживает SSE; текущее приложение использует обычный JSON. Email-вход требует интерактивного браузера. [Ограничения Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/#limitations).

Долгий ответ модели нужно проверить через сам HTTPS-адрес: прокси имеет собственные таймауты, а успешный локальный вызов не доказывает успешный ответ на телефоне. Cloudflare указывает стандартный Proxy Read Timeout 125 секунд; при его превышении возможен `524`. [Описание ошибки](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-5xx-errors/error-524/).

Туннель требует исходящих соединений к Cloudflare на порту 7844; скрипт не меняет сетевые правила. Он запускает runtime через список аргументов без shell, с пустым отдельным config, очищенным окружением, локальным metrics endpoint и единственной фиксированной целью `http://127.0.0.1:8000`. Пользовательские настройки `cloudflared` и переменные API-ключей не передаются дочернему процессу. [Параметры и сеть Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/configuration/). Host header не переопределяется: API сохраняет свою проверку соответствия браузерного Origin и Host, которую следует проверить через выданный адрес после разрешённого запуска.
