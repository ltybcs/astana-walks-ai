# Сценарий видеодемонстрации

Ориентир: 2–3 минуты, при медленной локальной модели допустима большая фактическая длительность. Запись показывает текущий интерфейс, реальную уличную карту и набор из 1267 объектов OSM. Все точки старта смоделированы. Перед записью закройте консоль с окружением и вкладки с личными данными. Не показывайте API-ключи. Старый ролик с 738 POI и схемой сохранён в истории и не демонстрирует новую карту.

PWA установлена на настоящий телефон с Android и Chrome и открыта по иконке со слов пользователя (20 октября 2026). Модель устройства не названа, offline на телефоне не проверен. Firefox пока сопровождается инструкцией; успешная установка не подтверждена. Снимки узкого браузерного viewport подписываются как браузерная проверка. Временный HTTPS-адрес зависит от ПК и туннеля.

Утверждать подключение LLM можно только при подтверждённом запросе, соответствующей маркировке интерфейса и зафиксированном отчёте. Не ускоряйте и не склеивайте ожидание так, чтобы оно создавало ложное впечатление о задержке сервиса.

## Альтернативная живая демонстрация

При ограниченном времени покажите прогулку EXPO, затем строгий запрос «тихое кафе с розеткой». Эти два примера раскрывают и полезную выдачу, и честную обработку неполных данных. Остальные три сценария и автоматические проверки жюри может повторить по документу.

## Выступление со слайдами

Полная речь формируется в `output/speaker-script.md` из тех же фактов, что презентация. Выступление рассчитано на 5–7 минут с паузой на ответ приложения. Хронометраж ориентировочный: перед сдачей нужна репетиция вслух. При сокращении оставьте сценарий, RAG, карту, источники, приватность, ограничения и бизнес-гипотезу.

## Сборка MP4 из состояний интерфейса

Когда непрерывная запись недоступна, `scripts/build_demo_video.py` собирает MP4 из фактических JPEG/PNG с подписями. Видео явно сообщает, что это смена состояний приложения, и не показывает скорость ответа. Оно без звука, 1920×1080, H.264, 25 кадров/с. Скриншоты масштабируются с сохранением пропорций, а подписи располагаются за их пределами.

Манифест JSON содержит `title` и `scenes`. Каждая сцена содержит относительный к манифесту путь `image`, точную подпись `caption` длиной до двух строк и `seconds` от 3 до 60. Используйте пять реальных состояний по сценариям задания. При неполных данных подпись должна описывать фактический отказ или уточнение, а не ожидаемый успешный ответ.

```sh
python scripts/build_demo_video.py output/demo-scenes.json --output output/astana-walks-demo.mp4
```

Скрипт ищет `ffmpeg` в PATH, затем в установленном `imageio-ffmpeg`, включая `.local/python`. Можно передать `--ffmpeg-path`. Рядом с роликом создаётся `.evidence.json` с SHA-256 исходных изображений, подписями и длительностью сцен.

## Публикация YouTube с доступом по ссылке

Пользователь решил загрузить готовый MP4 самостоятельно позже и прислать URL. До получения адреса `video_url` остаётся `null`; материалы и локальный ролик готовятся сейчас, без повторного запроса входа или публикации от имени пользователя.

1. Просмотрите весь готовый MP4: читаемость, фактические результаты, режим, отсутствие секретов и личных координат.
2. Загрузите ролик в свой YouTube Studio. Заголовок: «Astana Walks: демонстрация сценариев Smart City». В описании укажите прототип, источник OpenStreetMap, приблизительные времена и репозиторий с необходимым доступом.
3. Выберите «Доступ по ссылке» (Unlisted). Это внешняя публикация, ссылка может пересылаться получателями.
4. Проверьте полученную ссылку в отдельном окне без входа. Убедитесь, что жюри видит видео и может открыть остальные материалы.
5. Добавьте реальную ссылку как `video_url` в конфиг сборки и повторите сборку материалов. Наличие локального MP4 само по себе не подтверждает выполнение требования YouTube.
