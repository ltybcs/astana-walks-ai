Проверка оболочки не заменяет живой поиск; результаты ограниченной проверки записаны в [QA-протоколе релиза](../qa/public-route-release.json).

Исторический раздел отката `app.server` ниже относится к раннему интерфейсу. Для текущего единого помощника используйте команды выше.

## Настройки и основной запуск 8000

Команды выполняются из checkout, содержащего принятую единую версию. Замените четыре значения в угловых скобках **абсолютными существующими путями**; это пути к приватным файлам, не содержимое ключей. Не создавайте новые ledger вместо действующих.

```powershell
$taskCheckout = '<absolute-unified-checkout>'
$taskPrimary = '<absolute-primary-workspace>'
$taskGoogleConfig = '<absolute-existing-google-config.json>'
$taskEmbedConfig = '<absolute-existing-embed-config.json>'
Set-Location -LiteralPath $taskCheckout
$env:LLM_BASE_URL = 'http://127.0.0.1:8081/v1'
$env:LLM_MODEL = 'astana-local'
$env:LLM_JSON_MODE = 'schema'
$env:LLM_TOKEN_PARAMETER = 'max_tokens'
$env:LLM_TIMEOUT_SECONDS = '120'
python -B -m app.google_lab --host 127.0.0.1 --port 8000 --llm --google --google-config $taskGoogleConfig --dgis-root $taskPrimary --map-config $taskEmbedConfig --public-origin https://journey-tank-arrive-overcome.trycloudflare.com --frame-parent-origin https://ltybcs.com
```

Перед запуском завершите только прежний процесс приложения на 8000. Порт 8081 должен уже обслуживать закреплённую локальную модель. Не запускайте `run_demo.py`: он относится к старому приложению и может создать второй процесс модели. Туннель продолжает направлять тот же публичный адрес на loopback 8000.

Google config содержит `key_file` и **тот же** `ledger_file` существующего пилота. Разрешённый общий потолок Google — **750 попыток** после явного повышения существующего ledger; начальная инициализация по-прежнему создаёт лимит 500. Optional `cache_dir` относится лишь к историческим отдельным endpoints; смешанные ответы никогда не архивируются. `$taskPrimary` содержит существующие `.local/2gis/api-key`, `usage.json`, `usage.lock`: используется прежний ledger, а разрешённый пользователем предел теперь составляет 500 попыток 2ГИС за скользящие 30 дней (2 592 000 секунд), включая ошибки. Автоматического сброса нет; новый процесс не получает новый бюджет. Однократная операторская корректировка начальной отметки до подтверждённых провайдером 10 вызовов выполняется только по явному запросу пользователя с сохранением прежнего состояния и метаданных. Пути/ключи не коммитятся, значения ключей не передаются в CLI.

Embed config содержит `{"embed_key_file":"<absolute-dedicated-browser-key>"}`. Отдельный ключ намеренно доступен браузеру, ограничен **только Maps Embed API** и пятью referrers:

```text
http://127.0.0.1:8000/*
http://localhost:8000/*
http://127.0.0.1:8003/*
http://localhost:8003/*
https://journey-tank-arrive-overcome.trycloudflare.com/*
```

Backend Places/GML key в iframe запрещён. `--public-origin` разрешает только указанный HTTPS origin в проверках Host/Origin; это не wildcard для Cloudflare и не отключение проверки POST. Слушатель остаётся loopback. Iframe передаёт только origin страницы как referrer; пользовательский запрос и GPS в referrer не включаются.

## Локальный предпросмотр 8003

Используйте те же конфигурации, ledger и 8081. Отдельный процесс увеличивает нагрузку и расходует **те же**, а не новые лимиты:

```powershell
python -B -m app.google_lab --host 127.0.0.1 --port 8003 --llm --google --google-config $taskGoogleConfig --dgis-root $taskPrimary --map-config $taskEmbedConfig
```

Не добавляйте `--public-origin` к локальному предпросмотру без необходимости. Не запускайте одновременно конкурирующие live QA на обоих портах. GET `/api/unified/status` показывает локальную безопасную диагностику без нового провайдерского запроса.

## Явное повышение Google до 750

Сначала обновите и перезапустите **оба процесса приложения, 8000 и 8003**, чтобы их декодеры принимали ledger с лимитом 500 и 750. Только после этого выполните явное повышение из обновлённого checkout. Модель 8081, туннель, ключи и учёт 2ГИС не меняются.

Укажите абсолютный путь **существующего общего Google ledger**, который уже задан в `ledger_file` обеих конфигураций:

```powershell
$taskGoogleLedger = '<absolute-existing-google-ledger.json>'
python -B -m app.google_budget --raise-to-750 $taskGoogleLedger
```

Операция под существующей межпроцессной блокировкой повышает только лимит и время обновления; расход `used`, счётчики `operations` и исходный `initialized_at` сохраняются. Повтор для уже установленного 750 идемпотентен и не расходует вызовы. Отсутствующий или повреждённый ledger отклоняется; новый файл вместо него не создаётся. Приложение не повышает лимит автоматически. `--init` по-прежнему создаёт только новый счётчик на 500 и не используется для повышения или сброса существующего.

## Семантическая подготовка запроса

Приложение сначала валидирует входные поля, затем может обратиться к локальной модели для извлечения намерения. Поиск занятий, маршруты и итоговая генерация требуют подтверждённого старта. Явно названное незнакомое место проверяется одним Places Text Search; при неразрешённом старте нет городской точки по умолчанию.

Операция `places.resolve` расходует **тот же общий Google ledger с разрешённым потолком 750 попыток**, включая ошибки, а не отдельный бюджет. Сохранённый лимит становится 750 только после явной операции повышения выше. Перед первым новым вызовом обновите и перезапустите **оба процесса приложения, 8000 и 8003**, чтобы оба декодировали новый тип записи ledger. Модель 8081 и туннель ради этого не перезапускаются. Не исправляйте счётчик вручную и не создавайте новый ledger.

`/api/context` с согласием возвращает непрозрачный одноразовый preparation_token. План, координаты и подготовленный контекст хранятся только в ограниченной RAM с истечением срока; изменение формы, повтор токена или перезапуск процесса делает его недействительным. При продолжении с GPS сохраняется тот же план. Это не долговременный кэш ответа.

Извлечение и итоговая генерация используют общий ограниченный по времени model gateway. Межпроцессный lock расположен в папке действующего primary Google ledger, отдельно от самого ledger; у основного приложения и предпросмотра должны быть одна конфигурация и доступ к этой папке. Это предотвращает одновременную нагрузку на одну модель; ожидание входит в дедлайн, автоматического повтора inference нет.

## Проверка после переключения

Codex A фиксирует deployed commit/source SHA и результат по фактическому публичному адресу. Нужно различать загрузку оболочки, поиск и модель: manifest/icons/service worker могут работать при недоступном внешнем источнике.

- Первое открытие: одно поле, одна кнопка, без провайдерских переключателей и начальной карты.
- Неподтверждённый старт/отказ GPS: явная ошибка, ноль поиска занятий, маршрутов и итоговой генерации. Локальный разбор сообщения и отдельная попытка разрешить названное место учитываются отдельно.
- Разрешённый сценарий: отдельные receipts трёх источников, один полный ответ и описания по собственным фактам остановок либо честно обозначенный fallback; все Google previews сохранены.
- Построенный путь: единственная Google-карта соответствует принятому типу маршрута — возвращение к старту для кругового плана или отдельный финиш для A→B. Проверенный прямой путь без остановок допустим только с явной пометкой; он не считается выполнением пожелания о заведении. Другой ready-вариант не запускает новый поиск/LLM. Сверьте координаты старта, финиша и остановок с принятым планом: наличие iframe или знакомого названия само по себе не подтверждает правильный маршрут.
- Установка: прежние manifest id/start_url/scope; новый `astana-walks-shell-v11-point-to-point` удаляет только известные shell caches. Нет автоматической перезагрузки посреди запроса. Кэшируется только allowlisted оболочка; API, query strings, ответы, координаты, cross-origin карты не кэшируются.

Проверка телефона прежней версии не считается проверкой новой установки. Исторические receipts сохраняются; тексты и сырые данные провайдеров при новой QA на диск не пишутся.

## Откат без reset рабочей копии

Сначала завершите только единый процесс 8000. Из Git checkout с доступом к origin подготовьте **новую отсутствующую папку**. Эти команды не меняют текущие файлы и ветку:

```powershell
$taskRollback = 'C:\Users\ltybcs\Documents\ChatGPT\astana-walks-before-unified-2026-10-20'
if (Test-Path -LiteralPath $taskRollback) { throw 'Выберите новую отсутствующую папку отката.' }
git fetch origin tag checkpoint/before-unified-2026-10-20
git worktree add --detach $taskRollback checkpoint/before-unified-2026-10-20
Set-Location -LiteralPath $taskRollback
Remove-Item Env:DGIS_API_KEY -ErrorAction SilentlyContinue
python -B -m app.server --host 127.0.0.1 --port 8000 --data "$taskPrimary/data/poi.astana.json" --refresh-poi
```

Сохраните LLM env из раздела запуска: старый `app.server` читает его автоматически и **не имеет флага `--llm`**. В новой чистой worktree нет приватного runtime 2ГИС, поэтому отдельная панель 2ГИС при таком откате будет недоступна. Команда удаляет унаследованный DGIS_API_KEY только из текущего процесса PowerShell, чтобы не открыть новый счётчик в новой папке. Не копируйте ключ или ledger и не создавайте новый бюджет. Для полного восстановления старого 2ГИС интегратор отдельно возвращает прежний primary-процесс с его существующим runtime и проверенными исходниками.

Модель 8081 и HTTPS-туннель остаются прежними. Проверьте публичную загрузку старого интерфейса и его service worker после отката; не считайте браузерный кэш доказательством версии. Не используйте `git reset --hard`, force push или перенос поверх существующей рабочей папки.
