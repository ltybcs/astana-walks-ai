# Материалы для сдачи

Задача №1 НИЦ Smart City: «ИИ-помощник по прогулкам в городе Астана». Презентация рассчитана на 5–7 минут. В задании также запрошены документ сценариев и ограничений, репозиторий или архив прототипа и демонстрация на YouTube с доступом по ссылке.

Репозиторий остаётся закрытым. Ссылка не даёт жюри доступ автоматически. Для передачи без дополнительных приглашений используйте разрешённый условием переносимый ZIP с исходниками и материалами. Это отдельный вариант сдачи, не изменение приватности GitHub.

Итоговые файлы после сборки:

- `output/presentations/astana-walks.pptx` — редактируемые слайды и речь в заметках.
- `output/pdf/astana-walks-presentation.pdf` — 9 слайдов, формат 16:9.
- `output/pdf/astana-walks-scenarios.pdf` — сценарии, фактические результаты, ограничения, приватность и команды повторения.
- `output/speaker-script.md` — речь с ориентировочным хронометражем 6:30.
- `output/submission-facts.json` — источник чисел, даты и SHA-256 набора/отчёта.
- `output/evaluation.json` — фактический отчёт пяти сценариев и автоматических тестов.

## Повторение сборки

Сначала соберите реальные POI и сформируйте отчёт. Сервер и сценарная оценка используют один и тот же набор.

```sh
python -m app.evaluate --data data/poi.astana.json --output output/evaluation.json --run-tests
python -m app.server --data data/poi.astana.json
```

Сохраните фактический JPEG или PNG интерфейса с ответом первого сценария. Снимки CUA в этом проекте содержат JPEG и хранятся с расширением `.jpg`. Используйте смоделированную точку старта, чтобы не сохранять личную локацию. Не подменяйте скриншот макетом или сгенерированным изображением.

Для сборки артефактов нужны Python с `reportlab`, `pypdf`, `Pillow`, Node.js и `@oai/artifact-tool`. В Codex эти зависимости есть в bundled runtime. Приложение само по себе работает без них. Пути рантайма можно задать через `CODEX_ARTIFACT_RUNTIME`, `CODEX_RUNTIME_NODE`, `CODEX_RUNTIME_PYTHON`, `ARTIFACT_TOOL_MODULE` и `CODEX_PRESENTATIONS_SKILL`. На другой системе также задайте файлы шрифтов `ASTANA_FONT` и `ASTANA_BOLD_FONT` с кириллицей.

```sh
python scripts/build_submission.py --data data/poi.astana.json --evaluation output/evaluation.json --screenshot output/demo-ui.jpg
```

Необязательный `--config` принимает JSON с `video_url` и `llm`: `provider`, `model`, `live_verified`, `evidence`. Ключи туда не записываются. `live_verified` становится истинным только вместе с подтверждением живой LLM в отчёте оценки. Отсутствие такого подтверждения явно отражается в документах и слайдах. Поле `screenshot_crop` с долями `left`, `top`, `right`, `bottom` позволяет убрать в слайде декоративные поля скриншота. Исходный снимок сохраняется целиком без перекодирования; формат и MIME определяются по содержимому, SHA-256 сохраняется в фактах сборки. Предупреждения, режим и источник результата нельзя вырезать.

Скрипт откажется собирать финальные материалы из учебного набора, при отсутствии скриншота, при несовпадении набора с SHA-256 отчёта, без пяти успешных сценариев и пройденных автоматических тестов, а также при зафиксированном `manual_review.quality_pass: false`. Он не заменяет ручную оценку релевантности.

Слайды экспортируются через `@oai/artifact-tool`, проходят проверку структуры, размеров, шрифта и повторного импорта. Промежуточные PNG и отчёт валидатора находятся в `tmp/submission/`. PDF слайдов использует эти PNG, редактируемая версия находится в PPTX.

## Переносимый архив

После финальных проверок и коммита Codex A собирает архив из отслеживаемых файлов проверенного коммита, например через `git archive HEAD`. Архив должен содержать README с запуском, приложение, реальные POI с происхождением/лицензией, сборщик, тесты, документацию и итоговые PDF/PPTX. Демо MP4 можно включить, если размер позволяет передать его вместе с проектом. Работу Git в общем checkout продолжает выполнять Codex A.

В архив не входят `.git/`, `.local/`, `tmp/`, `.venv/`, `.env`, API-ключи, веса модели и журналы с пользовательскими данными. Локальная LLM загружается воспроизводимым setup-скриптом отдельно. Без неё приложение сохраняет честный extractive fallback. Перед передачей распакуйте ZIP в отдельную папку и проверьте запуск по README. Архив не заменяет требуемую заданием YouTube-ссылку.

## Визуальная проверка и видео

После сборки отрендерите все страницы PDF через Poppler и просмотрите каждый слайд и каждую страницу документа. Проверьте читаемость кириллицы, переносы, скриншот, источники и отсутствие обрезанного текста. После изменения метрик или интерфейса повторите сборку и просмотр.

[DEMO_SCRIPT.md](DEMO_SCRIPT.md) содержит последовательность короткой демонстрации. Видео в репозитории или локальный файл ещё не являются YouTube-публикацией. У итоговой ссылки отдельно проверяются доступ жюри и отсутствие секретов или личных координат в кадре.

## Мобильный интерфейс и PWA

На поддерживаемом браузере кнопка «Установить» вызывает системную установку или показывает инструкции. Для реального телефона нужен HTTPS-адрес сервиса. `http://localhost` и `http://127.0.0.1` подходят для локальной разработки на том же устройстве; обычный HTTP-адрес компьютера в Wi-Fi не получает это исключение. [Требования браузера к установке PWA, MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

При успешной регистрации service worker сохраняет только оболочку и иконки. Он не сохраняет ответы API, запросы или координаты. Вне сети новый подбор недоступен, приложение объясняет необходимость подключения. Это не полностью автономный городской справочник. При повторном подключении пользователь отправляет запрос заново.

20 октября 2026 пользователь подтвердил установку по HTTPS на настоящий телефон и запуск приложения по иконке. Это подтверждение пользователя; ОС и модель устройства не указаны, offline на телефоне не проверен.

Текущее временное демо: [entire-burn-cricket-ashley.trycloudflare.com](https://entire-burn-cricket-ashley.trycloudflare.com/). Оно доступно при включённом ПК и работающем Cloudflare Quick Tunnel. [output/https-check.json](../output/https-check.json) фиксирует 7/7 успешных проверок ресурсов и закрытых путей, включая manifest/SW/icon и отказы для исходника backend и `/v1/models`. Эта сетевая проверка отдельно от пользовательского подтверждения установки. Endpoint локальной модели не публикуется как отдельный сервис.

Конфиг сборки `pwa.enabled` добавляет эти возможности и ограничения в слайды, речь и PDF. `pwa.phone_evidence` указывает `output/phone-check.json`: статус установки со слов пользователя и границы проверки читаются из него в `pwa.phone_installation`. `pwa.https_evidence` указывает отдельный фактический отчёт ресурсов. Числа, даты и SHA-256 берутся из JSON; адреса должны совпадать с временным демо. `narration_evidence` задаёт JSON принятых LLM-объяснений; ID и SHA-256 набора должны совпадать с текущим планом. `screenshot_layout: "detail"` размещает точную цитату проверочного прогона рядом с увеличенным фрагментом фактического интерфейса.
