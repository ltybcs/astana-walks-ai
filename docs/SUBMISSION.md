# Материалы для сдачи

Задача №1 НИЦ Smart City: «ИИ-помощник по прогулкам в городе Астана». Презентация рассчитана на 5–7 минут. В задании также запрошены документ сценариев и ограничений, репозиторий или архив прототипа и демонстрация на YouTube с доступом по ссылке.

Материалы собраны для версии с 1267 OSM POI, настоящей картой Leaflet/OpenStreetMap, обновлением OSM по согласию и отдельным живым поиском 2ГИС. Прежние материалы с 738 POI сохранены в `output/history/qwen3-4b/738-poi/`. Текущие PDF/PPTX используют утверждённые свидетельства и фактические снимки расширенной версии. Новый видеотейк принимается отдельно; YouTube-публикацию пользователь выполнит позже.

Репозиторий остаётся закрытым. Ссылка не даёт жюри доступ автоматически. Для передачи без дополнительных приглашений используйте разрешённый условием переносимый ZIP с исходниками и материалами. Это отдельный вариант сдачи, не изменение приватности GitHub.

Итоговые файлы после сборки:

- `output/presentations/astana-walks.pptx` — редактируемые слайды и речь в заметках.
- `output/pdf/astana-walks-presentation.pdf` — 10 слайдов, формат 16:9.
- `output/pdf/astana-walks-scenarios.pdf` — 6 страниц: сценарии, фактические результаты, ограничения, приватность и команды повторения.
- `output/speaker-script.md` — речь с ориентировочным хронометражем 6:45.
- `output/submission-facts.json` — источник чисел, даты и SHA-256 набора/отчёта.
- `output/evaluation.json` — фактический отчёт пяти сценариев и автоматических тестов.

## Повторение сборки

Сервер и сценарная оценка должны использовать один и тот же снимок. Для отдельной проверки сохраняйте результат в `tmp/`, чтобы не перезаписывать утверждённые свидетельства материалов.

```sh
python -m app.evaluate --data data/poi.astana.json --output tmp/evaluation-check.json --run-tests
python -m app.server --data data/poi.astana.json
```

Сохраните фактический JPEG или PNG интерфейса с ответом первого сценария. Снимки CUA в этом проекте содержат JPEG и хранятся с расширением `.jpg`. Используйте смоделированную точку старта, чтобы не сохранять личную локацию. Не подменяйте скриншот макетом или сгенерированным изображением.

Для сборки артефактов нужны Python с `reportlab`, `pypdf`, `Pillow`, Node.js и `@oai/artifact-tool`. В Codex эти зависимости есть в bundled runtime. Приложение само по себе работает без них. Пути рантайма можно задать через `CODEX_ARTIFACT_RUNTIME`, `CODEX_RUNTIME_NODE`, `CODEX_RUNTIME_PYTHON`, `ARTIFACT_TOOL_MODULE` и `CODEX_PRESENTATIONS_SKILL`. На другой системе также задайте файлы шрифтов `ASTANA_FONT` и `ASTANA_BOLD_FONT` с кириллицей.

```sh
python scripts/build_submission.py --data data/poi.astana.json --evaluation output/evaluation-live.json --screenshot output/demo-ui.jpg --config docs/submission-config.json
```

Для обновлённого профиля используйте конфиг `docs/submission-config.json`. Он задаёт `video_url`, модель и фактические изображения. Ключи туда не записываются. `live_verified` требует подтверждённого живого результата в отчёте; доли LLM/fallback берутся из `summary.llm`, без обещания, что каждый ответ генерировался моделью. Поле `screenshot_crop` задаёт доли краёв. Исходник сохраняется без перекодирования; MIME определяется по содержимому, SHA-256 записывается в факты. Предупреждения, режим и источник результата нельзя вырезать. Длинная цитата на слайде может быть точным начальным фрагментом с многоточием; полный текст сохраняется в свидетельстве.

Для карты нужны текущий `features.street_map.screenshot` и подтверждённый `screenshot_dataset_sha256`, равный SHA-256 входного набора. На снимке должны оставаться тайлы, точки и видимая атрибуция. `ui_evidence` задаёт отдельный отчёт UI: SHA-256 набора и снимка, запрос и бюджет должны совпасть. Параметры TTL OSM и ограничений 2ГИС сборщик материалов читает из констант реализации; флаги `available` описывают возможности, а не включают сеть или обновление.

Текущий LLM-протокол смешан по времени: четыре основных ответа повторно проверены новым guard без генерации, дополнительный семейный пресет сгенерирован отдельно. Принято пять ответов; шесть уникальных вызовов включают исторически отклонённый семейный ответ. Это не новый последовательный полный прогон. Точный протокол и сырые свидетельства перечислены в `output/llm-evidence/manifest.json`; автоматический pass не заменяет ручное чтение объяснений.

Формальный сценарий MEGA даёт 42 минуты. Фактический снимок интерфейса даёт 44 минуты: в UI-пресете другая публичная точка старта. Этот отдельный UI-ответ не прибавлен к числу вызовов формального смешанного протокола. Мобильные снимки показывают один ответ и адаптивную верстку в браузере, а не проверку пяти сценариев на физическом телефоне.

Скрипт откажется собирать финальные материалы из учебного набора, при отсутствии скриншота, при несовпадении набора с SHA-256 отчёта, без пяти успешных сценариев и пройденных автоматических тестов, а также при зафиксированном `manual_review.quality_pass: false`. Для сборки с подтверждённой живой LLM обязательны существующий файл объяснений и явное `manual_review.quality_pass: true` одновременно в нём и в отчёте оценки. Отсутствующий или незавершённый review не проходит эту проверку. Extractive-сборка с честной маркировкой не требует LLM-review. Скрипт не заменяет ручную оценку релевантности.

Слайды экспортируются через `@oai/artifact-tool`, проходят проверку структуры, размеров, шрифта и повторного импорта. Промежуточные PNG и отчёт валидатора находятся в `tmp/submission/`. PDF слайдов использует эти PNG, редактируемая версия находится в PPTX.

## Переносимый архив

После финальных проверок и коммита Codex A собирает архив из отслеживаемых файлов проверенного коммита, например через `git archive HEAD`. Архив должен содержать README с запуском, приложение, реальные POI с происхождением/лицензией, сборщик, тесты, документацию и итоговые PDF/PPTX. Демо MP4 можно включить, если размер позволяет передать его вместе с проектом. Работу Git в общем checkout продолжает выполнять Codex A.

В архив не входят `.git/`, `.local/`, `tmp/`, `.venv/`, `.env`, API-ключи, веса модели и журналы с пользовательскими данными. Локальная LLM загружается воспроизводимым setup-скриптом отдельно. Без неё приложение сохраняет честный extractive fallback. Перед передачей распакуйте ZIP в отдельную папку и проверьте запуск по README. Архив не заменяет требуемую заданием YouTube-ссылку.

## Визуальная проверка и видео

После сборки отрендерите все страницы PDF через Poppler и просмотрите каждый слайд и каждую страницу документа. Проверьте читаемость кириллицы, переносы, скриншот, источники и отсутствие обрезанного текста. После изменения метрик или интерфейса повторите сборку и просмотр.

[DEMO_SCRIPT.md](DEMO_SCRIPT.md) содержит последовательность короткой демонстрации. Видео в репозитории или локальный файл ещё не являются YouTube-публикацией. У итоговой ссылки отдельно проверяются доступ жюри и отсутствие секретов или личных координат в кадре.

## Передача готового видео пользователю

Прежний ролик 3:24,44 с 738 POI сохранён как [исторический MP4](../output/history/qwen3-4b/738-poi/output/video/final/astana-walks-demo.mp4). Он не показывает новую карту и расширенные данные. Актуальный тейк после проверки помещается в [astana-walks-demo.mp4](../output/video/final/astana-walks-demo.mp4), а текст публикации — в [PUBLISHING.txt](../output/video/final/PUBLISHING.txt). До принятия нового тейка эти текущие пути тоже могут содержать старые материалы.

Пользователь выбрал: «Загружу сам позже и пришлю ссылку». Загрузка и вход в YouTube остаются за пользователем.

1. Убедитесь, что принят новый MP4: его `manifest.json` соответствует актуальному набору и фактически наблюдённым ответам. Загрузите полный принятый MP4 в свой YouTube Studio, используя обновлённый `PUBLISHING.txt`, и выберите «Доступ по ссылке» (Unlisted).
2. Откройте полученную ссылку без входа в аккаунт и проверьте воспроизведение.
3. После публикации запишите настоящий URL в `video_url` файла `docs/submission-config.json`. Сейчас это поле честно равно `null`.
4. После внесения ссылки пересоберите материалы, проверьте изменившиеся страницы и обновите ZIP:

```sh
python scripts/build_submission.py --data data/poi.astana.json --evaluation output/evaluation-live.json --screenshot output/demo-ui.jpg --config docs/submission-config.json
```

Локальный MP4 и архив проекта доступны без YouTube, но не заменяют требуемую ссылку на опубликованное видео. Публикация пользователем отложена; фиктивная ссылка в материалы не добавляется.

### Описание нового тейка

Обновляйте описание по его собственным `manifest.json` и `observed-responses.json`: число POI, дату, запросы, фактические времена, режимы и главы. Формальный evaluator — другой прогон; нельзя переносить из него число LLM-вызовов или выдачу в описание видео. Для смешанного прогона укажите, где виден LLM, где fallback или объяснённый отказ. Прямые отрезки на настоящей карте остаются приблизительной схемой, не навигацией. Обновление OSM описывается как опциональное с TTL 24 ч при работающем сервере, а не гарантия актуальности каждого места.

Живые карточки 2ГИС нельзя сохранять в Git, ZIP, PDF, снимках или ролике. В тейке допустимы пустая панель, выбор категории, атрибуция и лимит; содержимое реальных ответов не записывается. Проверка сервиса фиксируется только безопасными кодами/числами, без названий и координат карточек. Место 2ГИС отдельно от OSM-карты и RAG, одна страница до 10 объектов, 20 попыток за скользящие 24 ч; ошибки тоже расходуют попытку.

После принятия нового тейка `video.current_mp4` указывает его путь, а `video.current_dataset_sha256` — актуальный набор. До этого оба поля пусты; старый MP4 не выдаётся за проверку расширенной версии. `video_url` остаётся `null` до самостоятельной публикации пользователем.

## Мобильный интерфейс и PWA

На поддерживаемом браузере кнопка «Установить» вызывает системную установку или показывает инструкции. Для реального телефона нужен HTTPS-адрес сервиса. `http://localhost` и `http://127.0.0.1` подходят для локальной разработки на том же устройстве; обычный HTTP-адрес компьютера в Wi-Fi не получает это исключение. [Требования браузера к установке PWA, MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

При успешной регистрации service worker сохраняет только оболочку и иконки. Он не сохраняет ответы API, запросы или координаты. Вне сети новый подбор недоступен, приложение объясняет необходимость подключения. Это не полностью автономный городской справочник. При повторном подключении пользователь отправляет запрос заново.

20 октября 2026 пользователь подтвердил установку предыдущей версии по HTTPS на настоящий телефон с Android и Chrome и запуск приложения по иконке. Это подтверждение пользователя; модель устройства не указана, offline и новые функции на физическом телефоне отдельно не проверены. Для Firefox пока доступна инструкция установки; успешная установка в нём не подтверждена.

Текущее временное демо: [entire-burn-cricket-ashley.trycloudflare.com](https://entire-burn-cricket-ashley.trycloudflare.com/). Оно доступно при включённом ПК и работающем Cloudflare Quick Tunnel. [output/https-check.json](../output/https-check.json) фиксирует успешные проверки ресурсов и закрытых путей, включая manifest/SW/icon и отказы для исходника backend и `/v1/models`; числа и SHA берутся из самого отчёта. Эта сетевая проверка отдельно от пользовательского подтверждения установки. Endpoint локальной модели не публикуется как отдельный сервис.

Конфиг сборки `pwa.enabled` добавляет эти возможности и ограничения в слайды, речь и PDF. `pwa.phone_evidence` указывает `output/phone-check.json`: статус установки со слов пользователя и границы проверки читаются из него в `pwa.phone_installation`. `pwa.https_evidence` указывает отдельный фактический отчёт ресурсов. Числа, даты и SHA-256 берутся из JSON; адреса должны совпадать с временным демо. `narration_evidence` задаёт JSON принятых LLM-объяснений; ID и SHA-256 набора должны совпадать с текущим планом. `screenshot_layout: "detail"` размещает точную цитату проверочного прогона рядом с увеличенным фрагментом фактического интерфейса.
