# Приватность и достоверность

Запросы и точные координаты используются в памяти для текущего ответа. Приложение не создаёт аккаунты и историю прогулок, не применяет аналитику и не сохраняет локацию в localStorage. В форме по умолчанию смоделированная точка; пользователь может вручную указать другую.

В режиме без LLM запрос обрабатывается локально. При включении внешней LLM провайдер получает распознанные категории интересов и варианты формулировок по извлечённым POI. Исходный текст пользовательского запроса и координаты пользователя не включаются в этот payload. Модель выбирает формулировки из закрытого набора: она не генерирует произвольный текст и факты. Ключ хранится только в окружении backend. Перед использованием внешнего провайдера нужно проверить условия обработки данных.

Сборщик POI обращается к публичному API по фиксированной городской области. Он не передаёт персональную историю прогулок. Ссылки на источники открываются только при выборе пользователем; приложение не загружает внешнюю карту, шрифты и аналитику автоматически.

Время в пути оценивается геометрически. Это не проверка безопасности маршрута, доступности переходов или фактического времени на дорогу. Ночная доступность, розетки, тишина и возможности для маломобильных людей требуют подтверждённых данных. Неизвестные значения должны сохраняться как неизвестные.

Учебные POI отделены от собранных данных. Для каждого реального POI сохраняются источник и дата сбора. Сгенерированные идеи действий не должны выглядеть как факты о текущем событии или услуге. Для следующей версии нужны свежесть данных, проверка часов, исправления от владельцев мест и оценка ответов людьми.
